# 태권뽑기

수업 도구에서 상품과 수량을 준비한 뒤 9가지 화면 터치 방식으로 진행하는 로컬 뽑기다. 서버·회원·결제 기능은 포함하지 않는다. 등록한 상품은 도장에서 직접 준비하고 전달한다.

## 구성

- 캡슐 뽑기, 돌려차기 룰렛, 미트 뽑기, 사물함 뽑기, 승급심사 두루마리, 도복 뽑기, 메달 뽑기, 호랑이 기합, 회전 송판.
- 띠 핀볼·운명의 띠(나무통)·격파 한 판는 3D 에셋을 적용하는 후속 작업으로 보류한다. 실행 가능한 메뉴에 포함하지 않는다.
- 회전 송판은 보류한 송판 격파 뽑기와 별개로 유지한다.
- 모든 동작은 가상 화면 터치다. 카메라·실제 타격·음성 기합을 인식하지 않는다. 호랑이 모드는 기합 버튼을 사용한다.

## 생성 에셋

기성 이미지 다운로드 대신 각 컨셉을 정하고 내장 이미지 생성 도구로 9종의 PNG를 새로 제작했다. 모든 최종 에셋은 프로젝트 `apps/mobile/assets/lucky/`에 포함한다. 사물함·미트·도복 등은 생성한 개체를 반복 배치하고, 룰렛은 생성 원판을 실제 회전시킨다. 번호와 상품명은 이미지에 넣지 않고 화면에서 표시한다. 3D 모델은 포함하지 않는다.

- [미트·사물함·두루마리 프롬프트](lucky-assets-b-prompts.md)
- [도복·메달·호랑이 프롬프트](lucky-assets-c-prompts.md)

## 상품 준비와 확률

상품은 1~20종이며, 이름은 1~30자, 각 수량은 1~100개, 전체 수량은 1,000개까지 설정한다. `상품`과 `다음 기회`를 구분하며 다음 기회 역시 실제 수량을 가진 한 장의 뽑기다. 기본 예시로 칭찬 스티커·모두의 박수·다음 기회를 제공한다.

남은 수량 한 개를 한 장의 표로 취급한다. 예를 들어 A 1개, B 3개가 남았다면 A 확률은 1/4, B 확률은 3/4다. 뽑은 결과는 즉시 남은 수량에서 하나를 차감한다. 소진한 상품은 다시 나오지 않는다. 모든 수량이 0이면 새 추첨을 막고 새 회차 준비를 안내한다.

선택한 문·카드·미트의 위치와 버튼을 누르는 순간은 화면 연출이다. 모드 및 선택 위치는 상품 확률에 영향을 주지 않는다. 이 내용을 방식 선택 화면에 안내한다.

## 설정과 기록

- 상품 관리에서 수정 후 `상품 설정 저장하고 뽑기 준비`를 눌러 명시적으로 저장한다. 입력값을 자동 잘라내지 않고 정수·범위를 검증한다.
- 변경 사항을 저장하기 전에는 뽑기를 시작할 수 없다. 진행 화면에서는 상품을 수정하지 않는다.
- 이미 추첨한 회차의 상품 설정 변경이나 새 회차 시작은 확인을 거친다. 확인 후 기존 기록을 지우고 처음 수량으로 재설정한다.
- 결과 기록은 이번 회차의 모든 결과(최대 1,000건)를 보관하며 최근 20건부터 추가로 펼쳐 볼 수 있다.
- 별도의 추첨 결과 공개 여부와 무관하게 상품이 확정되면 저장한다. 연출 중 화면을 나가도 결과 기록에서 확인할 수 있다.

## 저장과 실패 처리

`seolin.lucky-draw.v1`의 단일 JSON에 상품 설정·남은 수량·결과 기록을 함께 저장한다. `LuckyStore`의 공유 인스턴스가 겹치는 요청을 차단하고, 매번 최신 저장 내용을 읽어 추첨한다. 결과 전달은 해당 변경의 저장 완료 뒤에만 이루어진다.

저장 데이터의 형식, 상품 ID, 결과 ID 중복, 결과와 상품의 연결, 설정 수량에서 결과 횟수를 뺀 남은 수량을 모두 검증한다. 손상 또는 읽기 실패 시 기본값으로 기존 데이터를 덮어쓰지 않는다.

쓰기 오류가 발생하면 동일 문서가 실제 저장되었는지 한 번 읽어 확인한다. 기존 문서가 그대로 남은 경우에는 실패를 안내하고 재시도를 허용한다. 읽기까지 실패하거나 예상하지 못한 문서가 확인되면 저장 결과를 알 수 없는 상태로 잠근다. 이때는 기록을 성공적으로 다시 불러오기 전까지 추첨·설정 변경·초기화·임시 모드 전환을 막아 추가 차감을 방지한다. 저장 결과가 확실한 일반 실패에서는 재시도하거나 `임시 모드`를 명시적으로 선택할 수 있다. 임시 모드는 기존 저장 내용을 바꾸지 않으며 화면을 나가면 임시 결과가 사라진다. 임시 모드에서도 같은 수량 차감과 중복 요청 방지를 적용한다.

`LuckyExperience`는 `onDraw(selectedIndex?)`를 통해 결과를 요청하며, 부모의 저장 완료 결과를 받은 뒤 연출한다. `onReveal`은 화면 공개 알림용이며 수량 차감이나 저장을 다시 수행하지 않는다.

## 검증

자동 검증 항목:

- 9종 모드 ID의 고유성, 남은 수량에 비례한 추첨 경계
- 소진 상품 제외·다음 기회 차감·정확한 전체 소진
- 모드·선택 위치에 따른 결과 확률 불변
- 정수/개별 수량/전체 수량 검증, 손상된 재고·중복 기록 거부
- 기록과 재고의 단일 저장, 새 저장소 인스턴스의 기록 복원
- 저장 실패 후 재고 유지 및 재시도, 동시 추첨 거부
- 손상 데이터 덮어쓰기 방지, 오류 응답 후 실제 저장 여부 확인
